DEMO REPO SETUP SPEC
=====================

CONTEXT (read this first)
--------------------------
I'm building a demo for an MCP (Model Context Protocol) gateway that sits in front
of GitHub and enforces access control for two AI agents: an "Issue Triage" agent
and a "PR Review" agent. The gateway's policy decisions depend on real data in two
GitHub repos (file paths, issues, and pull requests), so the demo needs those repos
to exist with specific, minimal content before it can be run end to end.

Your job is ONLY to create these two GitHub repos and populate them with the exact
content below. You are not writing any application code -- this is pure GitHub
content setup (repos, files, labels, issues, pull requests).

Use the `gh` CLI if it's available and authenticated (preferred), or the GitHub API
directly. Confirm which GitHub account/org you're creating these under before you
start, since the owner name needs to be reported back (see "What to report back"
at the end).

HARD CONSTRAINTS -- DO NOT DEVIATE
-----------------------------------
1. Repo names must be EXACTLY `storefront` and `payments-api` (lowercase, as
   written). The gateway's policy config references these names literally.
2. `storefront` must be PUBLIC. `payments-api` must be PRIVATE.
3. Both repos must be created under the SAME owner (same user or org).
4. Do NOT use any realistic-looking secret value anywhere (no strings matching
   patterns like `ghp_...`, `github_pat_...`, `AKIA...`, `sk-...`, or a PEM private
   key header). GitHub's push protection / secret scanning will block the commit
   if you do. The `.env` files below only need to exist AT THAT PATH to serve their
   purpose in the demo -- their content is irrelevant, so use the exact placeholder
   text given below, nothing fancier.
5. Pull requests must be left OPEN. Do not merge them, do not close them.
6. Do not add any labels to the issues when creating them (the demo agent applies
   labels later -- issues should start unlabeled).
7. Keep everything else about these repos as default as possible (default branch
   `main`, no extra files, no extra branch protection, no CI).

-------------------------

-----------------------------------

        return "ok"

3. Commit that change and open a pull request from `fix-checkout-alignment`
   into `main`:

     Body: Adjusts layout for small screens.
4. Leave this PR OPEN. Do not merge it.
